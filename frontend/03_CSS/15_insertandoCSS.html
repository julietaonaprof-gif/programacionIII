Las 3 formas de aplicar CSS

Este archivo aplica las tres formas oficiales al mismo elemento para que veas cómo interactúan.

Forma 1 — CSS Externo (<link>)

El archivo estilos.css se enlaza desde el <head>. Ahí le dimos a .demo un color azul y fondo celeste.

En el HTML:

<link rel="stylesheet" href="estilos.css">

En estilos.css:

.demo {
  color: blue;
  background-color: #e8f0fe;
  border-left: 4px solid blue;
}

Forma 2 — CSS Interno (<style>)

Los estilos van dentro de la etiqueta <style> en el <head>. Acá dentro pisamos el estilo externo y le dimos a .demo color verde.

En el HTML (dentro del head):

<style>
  .demo {
    color: green;
    background-color: #e8fae8;
    border-left-color: green;
  }
</style>

Esta caja está estilizada con CSS interno. El fondo color crema y el borde naranja punteado vienen de la regla .cajita-interno que está en el <style> de arriba.

Forma 3 — CSS en Línea (atributo style)

Se aplica directamente en el elemento con el atributo style="...". Es la más fuerte de las tres (mayor especificidad), así que SIEMPRE gana sobre las otras, salvo que otra regla use !important.

En el HTML:

<p style="color: red; background-color: #ffe8e8;">
  Texto con CSS inline
</p>

La batalla: las 3 formas peleando por el mismo párrafo

Los tres párrafos de abajo usan class="demo". Miralos:

PÁRRAFO 1 — Solo con class="demo".
Acá NO hay style inline. El CSS interno (verde) le gana al externo (azul) porque viene después en el <head>.

PÁRRAFO 2 — Con class="demo" Y style inline.
Acá el inline (rojo) le gana a todo, porque tiene mayor especificidad que las clases.

PÁRRAFO 3 — Con inline Y !important en el interno.
Acá el !important rompe la jerarquía y gana él (naranja).

¿Cuál gana cuando hay conflicto? La Cascada

Orden de prioridad (de menor a mayor), según el W3C:

  1. Estilos por defecto del navegador (lo más débil).
  2. CSS externo (<link>).
  3. CSS interno (<style>).
  4. CSS inline (style="...").
  5. !important en cualquier lugar (gana SIEMPRE salvo contra otro !important con más especificidad).

Pero ojo: el orden externo/interno/inline que di arriba es una simplificación. En realidad, entre externo e interno no gana el tipo de declaración, gana el ORDEN de aparición y la ESPECIFICIDAD.

En este archivo, el CSS interno gana al externo solo porque el <style> viene DESPUÉS del <link>. Si lo pusieras antes, ganaría el externo. Lo único que siempre gana por tipo es el inline (por tener mayor especificidad), y por encima de todo, !important.

¿Cuándo usar cada forma?

CSS Externo — USO PRINCIPAL

  • Proyectos reales con varias páginas.
  • Sitios donde importa el rendimiento (caché).
  • Siempre que sea posible. Es el estándar.

CSS Interno — CASOS ESPECÍFICOS

  • Prototipos rápidos, ejemplos, demos (como este archivo).
  • Páginas únicas que no comparten estilos con otras.
  • Emails HTML (muchos clientes ignoran CSS externo).
  • Estilos críticos "above the fold" para performance avanzada.

CSS en Línea — EVITAR EN GENERAL

  • Solo para ajustes puntuales y muy específicos.
  • Cuando lo genera JavaScript dinámicamente.
  • En emails HTML (es casi obligatorio ahí).
  • NUNCA para estilos sistemáticos: mezcla contenido con presentación, es imposible de mantener y no se puede cachear.
